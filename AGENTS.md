# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Durable product direction

- Match the live IQ Mentor interface and supplied screenshots one-to-one. Do not reinterpret, modernize, or add decorative design treatments.
- In the primary sidebar, replace the former Integrations entry with Settings.
- Settings must use existing IQ Mentor UI patterns. The entire LK settings group is intentionally omitted; keep the Analyst and Trainer sections working and clickable.
- In Settings, keep General neutral, use muted orange only as the Analyst accent, and use muted violet only as the Trainer accent; avoid large or bright color fills.
- All active Settings navigation rows use the same white background, neutral gray border, and dark text; category colors never tint the active-row background.
- Analyst and Trainer notification settings use the same Event / Display / Sound table layout; Analyst switches are muted orange and Trainer switches are muted violet, with independent working values.
- Settings → Analyst → Integrations contains Bitrix24, Yandex Disk, and amoCRM in one persistent service list with a contextual working detail panel. Service rows use recognizable brand logos with no secondary descriptions; preserve the supplied Yandex warning/OAuth flow and Bitrix token-management content.
- Put Documents under Settings → Общие and preserve the working document controls there; do not show Documents as a top-level sidebar destination.
- Put Employees under Settings → Общие and preserve the working employee controls there; do not show Employees as a top-level sidebar destination. Its department and table areas form one full-width surface joined by a single divider, flush with the Settings content bounds, without floating outer cards, horizontal drift, or clipped columns. On desktop, place Duplicate Search and Create Department in the same header row as the Employees title so the main workspace starts immediately below the header.
- Analyst and Trainer auto-report controls are full-width embedded Settings surfaces, not floating cards or overlays. Preserve the day/week/month toggles plus a single compact left-aligned Save button and Close behavior; do not add a Cancel button.
- Stereo call settings use one compact “Стереоформат звонков” dropdown with operator/client left-right presets. Do not show the former channel-recognition mode cards or separate channel-assignment controls. Its Save action matches the auto-report compact button styling, has no icon, and is left-aligned.
- Scoring settings are an embedded surface with minimum call duration, automatic analysis checkbox, Close/reset, and a compact left-aligned Save action. Do not restore the former category-weight sliders or strict-scoring toggle, and do not add a Back button inside Settings.
- Primary sidebar sections must be reorderable by holding the left mouse button and dragging. The dragged item follows the cursor, surrounding sections animate aside to expose a drop slot, and each user's chosen order persists locally between sessions.
- Keep a top-level “Тренер” sidebar destination with the source graduation-cap icon and chevron, positioned before “Настройки” by default and included in drag-and-drop ordering.
- On desktop, hovering a primary sidebar section should show a compact tooltip reading “Зажмите, чтобы переместить”; hide it immediately when the pointer leaves, while reordering, and on compact/mobile navigation.
- The current Home page source of truth is the supplied full analytics dashboard screenshot: use a compact header row, four vivid gradient KPI cards, a line chart, score-distribution donut, and three lower ranking/attention panels. Match its density, proportions, white surfaces, thin borders, and restrained typography while preserving the product's agreed navigation structure.
- Home dashboard widgets share one unified drag-and-drop grid: every widget can move into every slot, including charts into compact KPI positions and KPIs into large chart positions. The widget adapts to the destination geometry, surrounding cards move and resize smoothly around the landing slot, and the layout persists locally. Every widget can also be hidden from its three-dot action; remaining widgets compact forward and expose persistent free slots. Any visible widget can be moved into a free slot, transferring the empty position back to its source. A compact header action restores all hidden widgets.
- Home customization uses a Notion-like affordance: hovering a widget reveals a six-dot grip on its left edge, while the explicit customization mode keeps every grip visible, adds restrained widget outlines, and shows `Перетаскивайте виджеты` plus `Готово` in the header. `Настроить главную` opens a right-side widget catalog with search, category filters, per-widget add/remove controls, and individual persistence; free slots also open the catalog.
- Keep the minute-billing engine and its tested simulator logic in the codebase as decision-lab infrastructure, including the shared balance, Trainer reserve, settlement policies and ledger; it is intentionally not rendered on the product-facing tariff page.
- The product-facing “Тарификация” page is intentionally calculator-only. It estimates monthly AI Analyst usage from manager count, average monthly calls per manager and average call duration at 5 ₽/minute, then recommends AI Trainer at 25% of the Analyst budget and converts that recommendation to minutes at 12 ₽/minute. Analyst results are orange, Trainer results use the production purple `#6467F2`, and the centered combined budget uses a separate acid-green accent. Do not expose the earlier billing lab, top-up controls, trainer sessions, policies, or ledger on this page.
- “База знаний” opens the screenshot-matched “Помощь” modal over the current page: compact left navigation, black/gold case cards, module onboarding cards and the supplied chatbot/Telegram banners. Preserve the source composition and artwork without redesigning it.
- Knowledge-base help must adapt to the viewport rather than remain a 914×508 miniature: use readable 14px navigation, 20–24px primary headings, fluid card grids, and independent internal scrolling. On phones, move section navigation into a horizontal strip so the content keeps its usable width.
- Keep all three editable tariff questions together as compact full-width rows stacked above the results. Below them, show equal-width Analyst and Trainer cards, then place the total recommendation beneath them as a short standalone centered green result strip, without an enclosing white module card or a separate “Общий бюджет” heading. Its amount is visually larger than the module amounts. On narrow screens it expands to the available width and everything stacks cleanly.
- In each compact tariff question row, show the editable number separately and render a clean orange slider with a solid thumb without a white outline; keep quiet minimum and maximum labels below the track and do not duplicate the current value above the thumb.
- Use a subtle warm-orange gradient on the filled portion and thumb of active tariff sliders while keeping the unfilled track neutral gray.
- Use the same gradient slider, solid no-outline thumb, and min/max labels in the onboarding survey. The shared first question must use the orange accent for its progress bar, slider, and primary action rather than neutral gray.
- New or explicitly restarted surveys begin at the visible business averages: 10 managers, 600 monthly calls per manager, and 10 minutes per call. Mark each average above its onboarding slider with a small orange-ring circle and the quiet label “Среднее по бизнесу”; normal calculator revisits still restore the user's saved answers.
- In the editable calculator, animate Analyst, Trainer, and combined result amounts plus their hour values as eased numeric counters over roughly 900 ms whenever inputs change. Rapid changes continue from the currently displayed number without jumping; direct input controls remain immediate, and reduced-motion users see the final values instantly.
- Onboarding navigation must animate in sequence: fade/slide the current question out before mounting the next question or loading screen, and softly reveal the calculator after the three-second calculation screen. Prevent repeated navigation clicks during the exit transition and respect reduced-motion preferences.
- Apply the same warm-orange gradient language to onboarding primary actions and the calculation loading indicator; keep secondary Back actions neutral.
- After the three-second calculation loader, show a compact marketing-results card before the editable calculator. Reveal three bright, staggered benefit tiles calculated from the survey: Analyst listening hours saved, Trainer practice hours, and monthly calls analyzed. Provide two actions below: a primary route to customize the calculation and a secondary route to restart the survey; only mark onboarding complete when the user proceeds to the editable calculator.
- Keep the large Analyst and Trainer benefit values aligned to the same horizontal baseline even when one supporting caption wraps to an extra line.
- Keep tariff-question typography on Inter with real 500/600 weights, vertically balanced with the slider; module hover movement should be subtle and eased rather than a sharp jump.
- On desktop, use one fixed-width value column for every tariff question: right-align all numbers to the same edge and begin every unit label at the same horizontal position.
- Vertically align each desktop slider track with the lowered question text and numeric value rather than leaving the track visually above them.
- Reveal a centered “Пополнить баланс” CTA beneath the combined recommendation 2.5 seconds after a completed or updated calculation. Animate it in two phases: a small lime circle emerges from beneath the result strip, then expands horizontally into a fully rounded button before its white label fades in. Whenever calculator inputs or enabled modules change, run the sequence in reverse, restart the delay, then reveal it again for the updated calculation.

- Keep both lime recommendation surfaces shadow-free. Add quiet white product-pattern icons inside the expanding top-up/consultation bubble, matching the decorative language of the module and total result strips without reducing label legibility.
